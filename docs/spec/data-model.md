# Data model and `.mdj` mapping

Aster's internal model is a small, flat, id-keyed structure; `.mdj` is a nested tree with `$ref` links. The codec converts between them and carries anything it doesn't understand as an opaque blob so nothing is lost. The authoritative TypeScript shapes are in `src/lib/model/types.ts` (hand-authored).

## Export rules

Imported elements keep their `_id`; new ones get a 22-character base64url id in StarUML's style. `_parent` is always written. Every classifier view gets regenerated `UMLNameCompartmentView`, `UMLAttributeCompartmentView` and `UMLOperationCompartmentView` subviews (and a literal compartment for enums), with `UMLAttributeView` / `UMLOperationView` children whose `text` is the canonical rendered line, because StarUML reads those on open. Edge `points` are written with the node-border endpoints recomputed from the current layout. Unknowns are spliced back in document order. A golden-file test holds the fixture `.mdj` files and asserts equal output after a no-op load and save, ignoring key order.

## UML text grammar

What inline editing parses, both directions. This is StarUML's QuickEdit syntax (`[<<stereotype>>] [visibility] name [:type] [[multiplicity]] [=default-value]`) plus the UML property block, so a line pasted from StarUML parses unchanged.

```
attribute  := [stereo] [vis] ["{static}"] name [":" type] ["[" mult "]"] ["=" default] ["{" props "}"]
operation  := [stereo] [vis] ["{abstract}"|"{static}"] name "(" [param ("," param)*] ")" [":" type] ["{" props "}"]
literal    := [stereo] name
param      := ["in"|"out"|"inout"] name [":" type] ["=" default]
stereo     := "<<" name ">>"
vis        := "+" | "-" | "#" | "~"
mult       := "*" | int | int ".." (int | "*")
```

Parsing is forgiving (any whitespace, optional spaces around the colon); rendering is canonical (`- balance: Money = 0`). `⌘↩` while editing adds the next member below, `⌘⌫` deletes it, `⌘↑` / `⌘↓` reorder — the same keys StarUML uses. `fixtures/grammar/lines.json` is the parser's truth.
