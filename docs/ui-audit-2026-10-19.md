# UI / UX audit — 2026-10-19

Scope: every Svelte component under `src/lib/panels`, `src/lib/panels/classic`, `src/lib/canvas`, `src/routes`, the chrome tokens in `src/routes/layout.css`, and a runtime pass (28 screenshots of every state across the four themes and both layouts, axe on each, Tab walk). Standard: `docs/spec/ui.md`, `accessibility.md`, `keyboard.md`, the design boards in `docs/design/html/`, and the CLAUDE.md non-negotiables. Nothing was edited.

Status: **confirmed** = verified in code or on a screenshot by the lead; **reported** = found by a reviewer, code path read, not run in a browser.

Summary: 8 critical · 27 major · ~60 minor. Verdict: the chrome is coherent and board-faithful; the breakage is in states nobody looked at (dark and high-contrast overlays on white paper, editing with chords, Classic ARIA, the toolbox Link path) and in spec rows that were skipped without a DECISIONS line.

## Critical

1. **Status footer unreadable in dark and high contrast.** `src/routes/design/[slug]/+page.svelte:338` colours the footer `--chrome-muted`, but it sits on the canvas paper, which is always white. Dark 2.75:1, high contrast 1.25:1. Fix: a paper-side text token or a chrome plate behind the footer. _confirmed (screenshot)_
2. **"Lives only in this browser" banner unreadable in dark and high contrast.** `+page.svelte:364` hardcodes `color: #3f2a00` on a warning tint. Dark 1.3:1, HC 1.15:1. Fix: `var(--chrome-text)`. _confirmed_
3. **Open and drop errors on the welcome are silent.** `ImportNotice.svelte:231` is `z-index: 20`; `Welcome.svelte:175` is an opaque `z-index: 30` layer. DECISIONS says the welcome renders the notice; it renders it underneath. Fix: mount the notice inside Welcome or raise it. _confirmed (code)_
4. **Inline editor swallows every chord.** `LineEditor.svelte:92` and `NoteNode.svelte:29` call `stopPropagation()` on all keydown, so ⌘S opens the browser's save dialog mid-edit and ⌘Z, ⌘K, ⌘B, ⌘⇧E, ⌘⌥T are dead. Fix: stop propagation only for keys the editor consumes. _confirmed_
5. **A link started from the toolbox cannot be finished with a pointer.** `Canvas.svelte:257` picks the link target by arrow keys only; `Toolbox.svelte:72` leaves focus on the toolbox button so the arrows do nothing either until the canvas is clicked. Fix: node click sets the target; `canvasFocus.focus()` after `startLink()`. _confirmed_
6. **Invisible member-row buttons are hit-testable.** `MemberList.svelte:99`: the ↑ ↓ × overlay is `opacity-0` but not `pointer-events-none`, so a click at the right end of a member field moves or deletes the member. Fix: `pointer-events-none` until `group-hover` / `group-focus-within`. _confirmed_
7. **Classic Working Diagrams ARIA is invalid.** `WorkingDiagrams.svelte:11-22`: `ul role="listbox"` with `li` children and `role="option"` buttons, no arrow keys. axe: `aria-required-children`, `aria-required-parent` (critical), `listitem`. Fix: plain button list with `aria-current`. _confirmed (axe)_
8. **The canvas is not a Tab stop.** Tab from the strip: New diagram → Hide → Select → Show inspector → leaves the document. `role="application"` never receives focus. Scheduled as M2 canvas keyboard navigation; noted here because it is the single biggest a11y gap. _confirmed (Tab walk)_
